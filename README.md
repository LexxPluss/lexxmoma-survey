# LexxMoMa アンケート（試作）

1枚の画面で、アンケートに答えながら LexxMoMa の活用事例や構想を見てもらうための道具です。

| 場所 | 表示するもの | 中身の管理場所 |
|---|---|---|
| 上段（横いっぱい） | 一般情報（ごあいさつ・アンケートの目的など） | `content/items.md` の先頭 |
| 下段・左 | Google フォーム（アンケート） | Google フォーム |
| 下段・右 | 活用事例と今後の構想のカード。フォームを下に進めても見え続け、**回答中のセクションに合わせて切り替わります** | `content/items.md` のカード |

- スマホなど幅の狭い画面では、一般情報 → フォーム → 活用事例 の順に縦に並びます。
- 「みんなの回答」（全員の回答のグラフ表示）は今は止めています（付録参照）。
- 入口で**合言葉**を入れた人だけが画面に入れます（仕組みと注意点は「5. 合言葉の仕組み」）。
- 質問は Google フォームで管理します。フォームを編集すれば、画面にもそのまま反映されます。

```
lexxmoma-survey/
├─ index.html          画面
├─ css/style.css       見た目
├─ js/config.js        ★URL・合言葉などの設定（変更するのは基本的にここだけ）
├─ js/…                動きの部品（通常は触りません）
├─ content/items.md    ★一般情報と、活用事例・構想のカードの内容
├─ content/images/     ★カードの画像
├─ password-tool.html  合言葉を変えるときに使う変換画面
├─ gas/Code.gs         「みんなの回答」を使うときだけ必要
└─ start.bat           パソコンで画面を確認するとき用
```

---

## まずは画面を見てみる

1. `start.bat` をダブルクリックします（黒い画面が開き、ブラウザで画面が開きます）。
   - Python が入っていない場合は https://www.python.org/ から入れてください。
2. 合言葉を入れます（担当者から聞いてください。変え方は 2-2）。
3. 終わったら、黒い画面を閉じます。

> `index.html` を直接ダブルクリックすると、合言葉の確認や、一般情報・活用事例の読み込みが動きません。必ず `start.bat` から開いてください。

## 1. Google フォームの設定（社外の方が回答できるように）

フォームの **「設定」→「回答」** で次のようにします。

- **「（組織名）と信頼できる組織のユーザーに制限する」→ オフ**
- 「メールアドレスを収集する」→ **「収集しない」**（連絡先が必要なら「回答者からの入力」）
  - **「確認済み」にすると回答に Google へのログインが必要になり、画面の中のフォームが空白になります。**
- 「回答を1回に制限する」→ **オフ**（これもログインが必要になります）

設定したら、ログインしていないブラウザ（シークレット画面）でフォームの URL を開き、ログインを求められずに質問が表示されることを確認してください。

## 2. 設定する場所（`js/config.js`）

メモ帳などで `js/config.js` を開いて書き換えます。
`'`（半角の引用符）で囲むこと、行の最後の `,` を消さないことに気をつけてください。

### 2-1. フォームの URL

```js
FORM_URL: 'https://docs.google.com/forms/d/e/xxxxxxxx/viewform',
```

フォームの「送信」→ 🔗（リンク）の URL を入れます。「＜＞」（埋め込み）のコードをそのまま貼っても動きます。
**短縮 URL（forms.gle）は使えません。**「URL を短縮」のチェックを外してから写してください。

`FORM_HEIGHT` はフォームを表示する枠の高さです。質問が増えて枠の中で縦に動かす必要が出たら大きく、下の余白が多すぎるなら小さくしてください。

### 2-2. 合言葉を変える

合言葉は、そのままではなく「変換した文字列」で書いておきます（ページの中身を見ても、合言葉がすぐには分からないようにするため）。

1. `start.bat` で画面を開いた状態で、ブラウザの URL を `http://127.0.0.1:8749/password-tool.html` にします。
2. 新しい合言葉を入れると、`PASSWORD_HASH: '……',` という1行が出ます。
3. 「写す」を押し、`js/config.js` の `PASSWORD_HASH:` の行と置き換えて保存します。

- `PASSWORD_HASH: '',` と空にすると、合言葉なしで入れるようになります。
- `REMEMBER_HOURS` は、一度入れた合言葉を覚えておく時間です。0 にすると毎回入力になります。

### 2-3. セクションとの連動

```js
FORM_SECTIONS: 3,
SECTION_TITLES: ['現在の作業について', '自動化したい作業', '今後への期待'],
```

- `FORM_SECTIONS` に、Google フォームの**セクションの数**を入れます（0 にすると連動しません）。
- `SECTION_TITLES` は右側の上に出す名前です。空 `[]` なら「セクション 1」のように出ます。
- どのカードをどのセクションで出すかは、`content/items.md` の `セクション:` で決めます（3 を参照）。

**仕組みと限界**

- フォームの「次へ」「戻る」「送信」を押すと、フォームが読み込み直されます。画面はこれだけを検知して、右側を次のセクションに進めます。
- 外側の画面からはフォームの中身が見えないので、**「次へ」と「戻る」の区別がつきません。** 「戻る」を押すと右側が1つ先に進んでしまいます。
  そのときは、右側の上の **‹ ›** ボタンで合わせ直せます。
- 最後のセクションのあとの読み込みは「送信した」とみなし、`セクション: 送信後` のカードを出します。
  そのため **`FORM_SECTIONS` が実際のセクション数より少ないと、送信前に「送信後」の表示になります。** フォームを変えたら必ず合わせてください。
- 必須の質問が空のまま「次へ」を押した場合は読み込みが起きないので、右側は進みません（正しい動きです）。

## 3. 一般情報と活用事例の更新方法

`content/items.md` を書き換えるだけです。ファイルの先頭に書き方の説明があります。

```markdown
# 一般情報の見出し（画面の一番上に出ます）
一般情報の本文。最初の「## 」より前に書いたものが上段に出ます。

## カードの見出し（ここから右側のカード）
区分: 構想
時期: 2027年ごろ
画像: images/my-photo.jpg

本文を書きます。空行で段落が分かれます。
- 「- 」で始めると箇条書き
**太字** や [リンク](https://www.lexxpluss.com/) も使えます。
```

- `# `（シャープ1つ）は上段の見出し、`## `（シャープ2つ）から次の `## ` までがカード1枚です。カードは書いた順に並びます。
- `区分:` に書いた言葉ごとに、絞り込みのボタンが自動でできます（例：構想／事例）。
- `セクション:` に数字を書くと、フォームのそのセクションを回答している間だけ表示されます。
  `セクション: 1, 2` で複数、`セクション: 送信後` で送信したあと、書かなければ常に表示です。
- 画像は `content/images/` に入れて、`画像:` にファイル名を書きます。横長（16:9）、1枚 500KB 以下が目安です。
- 今入っている一般情報の文章、「（サンプル）」のカード、`sample-*.svg` はすべて仮です。差し替えるか消してください。
- 公開後は、GitHub の画面上でこのファイルを直接編集できます（4-4 参照）。

## 4. GitHub Pages での公開

### 4-1. 置き場所（リポジトリ）を作る

1. https://github.com にログインし、右上の **「＋」→「New repository」** を押します。
2. Repository name に名前（例：`lexxmoma-survey`）を入れます。
3. **Public** を選びます（無料で GitHub Pages を使う場合は Public が必要です。「5. 合言葉の仕組み」も読んでください）。
4. **「Create repository」** を押します。

### 4-2. ファイルを上げる

1. 作ったリポジトリの画面で **「uploading an existing file」**（または「Add file」→「Upload files」）を押します。
2. この `lexxmoma-survey` フォルダの**中身**（`index.html`・`css`・`js`・`content`・`.nojekyll`）を、ブラウザにドラッグして入れます。
   - フォルダごとではなく、**中身**を入れてください（`index.html` が一番上に来るように）。
   - `gas`・`start.bat`・`password-tool.html`・`README.md` は上げなくても構いません。
3. 下の **「Commit changes」** を押します。

### 4-3. 公開を有効にする

1. リポジトリの **「Settings」→ 左の「Pages」** を開きます。
2. 「Build and deployment」の Source を **「Deploy from a branch」**、Branch を **`main`** と **`/ (root)`** にして **「Save」**。
3. 1〜2分待って画面を再読み込みすると、上に `https://（ユーザー名）.github.io/lexxmoma-survey/` のような URL が出ます。これが公開 URL です。

### 4-4. 公開後に更新するとき

- `content/items.md` や `js/config.js` は、GitHub の画面でファイルを開き ✏（Edit）で直して「Commit changes」を押せば、1〜2分で反映されます。
- 画像を足すときは、`content/images` フォルダを開いて「Add file」→「Upload files」。
- `js` や `css` の中のファイルを変えたときは、`index.html` の `?v=10` をすべて `?v=11` のように1つ増やしてください（古いファイルがブラウザに残るのを防ぎます）。

## 5. 合言葉の仕組み（大事なので必ずお読みください）

- 今の合言葉は、**画面に入るための簡易な鍵**です。うっかり見られることは防げますが、
  詳しい人がページの中身を調べれば、合言葉なしで内容を見ることができます。
- GitHub Pages（Public）に置いたファイル（`content/items.md` や画像など）は、**インターネットに公開されたもの**として扱ってください。
  一般情報や活用事例に、社外に出せない情報は載せないでください。
- フォーム自体は、Google フォームの URL を知っていれば誰でも回答できます。

## 6. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「合言葉が違います」 | 2-2 で作った行を正しく貼ったか（前後の空白や全角・半角も確認） |
| 「合言葉を確認できませんでした」 | `https://` のページ、またはパソコンでは `start.bat` から開いているか |
| フォームが空白になる | 1 の設定をしたか／`FORM_URL` が forms.gle の短縮 URL になっていないか。フォームの上の「こちらから回答できます」からは回答できます |
| 一般情報や活用事例が出ない | パソコンでは `start.bat` から開いているか／`items.md` の見出しが `## `（半角シャープ2つ＋空白）か |
| 右側の表示がフォームとずれる | 右側の ‹ › で合わせ直せます。いつもずれる場合は `FORM_SECTIONS` が実際のセクション数と同じか確認 |
| 直したのに画面が変わらない | ブラウザで再読み込み（Ctrl＋F5）。`js`・`css` を直したときは 4-4 の `?v=` を増やす |

## 付録：「みんなの回答」を使う場合

回答結果を回答者全員で見られるようにする欄です（今は止めています）。使うと、フォームと活用事例の下に表示されます。
Apps Script でスプレッドシートの回答を取り出し、質問の形式に合わせて自動でグラフにします。

| フォームの形式 | 表示 |
|---|---|
| ラジオボタン・プルダウン | 棒グラフ（件数と割合） |
| チェックボックス | 横棒グラフ（割合は回答者数に対して） |
| 均等目盛・評価 | 分布の棒グラフ＋平均 |
| 記述式で、回答がすべて数字 | 平均・中央値・最小・最大 |
| 記述式（短文・長文） | 新しい順の一覧＋ことばで絞り込み |
| 選択式（グリッド）・チェックボックス（グリッド） | 行ごとの積み上げ横棒グラフ |

ほかに「最新に更新」ボタン、60秒ごとの自動更新、集計表の CSV 保存があります。

**試しに見るだけなら：** `js/config.js` の `SHOW_RESULTS` を `true` にすると、ダミーデータで表示されます（合言葉 `demo`）。

### A-1. コードを貼り付ける

1. フォームの回答が入る**スプレッドシート**を開きます（フォームの「回答」タブ →「スプレッドシートにリンク」で作ったもの）。
2. 上のメニューの **「拡張機能」→「Apps Script」** を押します。
3. 開いた画面の `コード.gs` の中身をすべて消し、`gas/Code.gs` の中身を**すべて**貼り付けて 💾（保存）。

### A-2. 公開しない質問を決める

`Code.gs` の上のほうにある `EXCLUDE_TITLES` に、公開したくない質問の**タイトルに含まれる言葉**を書きます（例：`'お名前'`、`'会社名'`）。
メールアドレスの収集の列や、シートに手で足した列は、もともと公開されません。

### A-3. 合言葉を登録する

1. 左側の **⚙（プロジェクトの設定）** →一番下の **「スクリプト プロパティを追加」**。
2. 「プロパティ」に `VIEW_PASSWORD`、「値」に合言葉を入れて保存します。

この場合は回答データそのものが合言葉で守られます（正しい合言葉がないと Apps Script がデータを返しません）。`config.js` の `PASSWORD_HASH` は使われません。

### A-4. 動くか確かめる

1. 上の関数を選ぶ欄で **`testOutput`** を選び **「実行」**。
2. 初回の承認：「権限を確認」→ 自分のアカウント →「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」。
3. 「実行ログ」に公開する質問の一覧と回答数が出れば成功です。除外したい質問が出ていないか確認してください。

### A-5. ウェブアプリとして公開する

1. **「デプロイ」→「新しいデプロイ」**→ 種類は **「ウェブアプリ」**。
2. 次のユーザーとして実行：**自分**、アクセスできるユーザー：**全員**。
3. 「デプロイ」を押し、**URL（最後が `/exec`）** をコピーします。
4. その URL の後ろに `?pw=合言葉` を付けてブラウザで開き、`{"ok":true, ...}` と出れば成功です。

> 「全員」が選べない場合は、会社の Google Workspace の設定で禁止されています。管理者に相談するか、個人の Google アカウントでフォームとシートを作ってください。
> Code.gs を直したあとは「デプロイを管理」→ ✏ → バージョン「新バージョン」で更新します（「新しいデプロイ」だと URL が変わります）。

### A-6. 画面側の設定

`js/config.js` で `SHOW_RESULTS: true,` にし、`API_URL:` に A-5 の URL を入れます。
